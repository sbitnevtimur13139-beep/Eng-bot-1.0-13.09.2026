# Speaking Bot — учебная веб-версия за один день

## Зачем этот файл

Это описание максимально упрощённой версии приложения для тренировки устного английского. Собирается за один день в рамках лекции, цель — потренироваться. Полная концепция продукта существует отдельно (там Telegram-бот и Mini App), здесь она урезана намеренно и переведена в веб, чтобы не возиться с webhook и Telegram API. Не добавлять функции сверх описанных, даже если они кажутся очевидными.

## Суть продукта

Одна страница в браузере. Пользователь нажимает кнопку записи, говорит по-английски, отпускает. Приложение транскрибирует, исправляет ошибки, коротко объясняет их на русском и отвечает как собеседник следующей репликой. Пользователь снова записывает ответ. Так по кругу, на экране это выглядит как чат.

## Стек

- Next.js (App Router, TypeScript), одна страница и два API-роута.
- Запись звука в браузере через `MediaRecorder`, формат `audio/webm`.
- OpenAI SDK на сервере: Whisper (`whisper-1`) для распознавания речи, `gpt-4o-mini` для исправления и ответа. Названия моделей в константах.
- Без базы и без авторизации. История диалога живёт в состоянии React на клиенте и передаётся на сервер с каждым запросом. Перезагрузка страницы = новый диалог.
- Стили — Tailwind из `create-next-app`, минимум оформления.

## Переменные окружения

```
OPENAI_API_KEY=
```

## Структура проекта

```
app/page.tsx                    # единственная страница, весь UI и состояние
app/api/transcribe/route.ts     # POST audio -> { text }
app/api/respond/route.ts        # POST { history, userText } -> { corrected, explanation, reply }
lib/stt.ts                      # transcribe(file) -> string
lib/llm.ts                      # respond(history, userText) -> { corrected, explanation, reply }
lib/prompt.ts                   # системный промпт и стартовая реплика, только константы
lib/types.ts                    # типы Message и RespondResult
```

Роуты не должны сами дёргать OpenAI: `transcribe` вызывает `stt.ts`, `respond` вызывает `llm.ts`. Ключ OpenAI живёт только на сервере, в клиентский код не попадает.

## Пользовательская логика

### Экран

Сверху — лента диалога. Снизу — одна большая кнопка записи и кнопка `Начать заново`.

При открытии страницы в ленте уже есть первая реплика собеседника на английском. Реплика одна, зашита в `prompt.ts`, например: `Hi! Let's talk. What did you do last weekend?`

`Начать заново` очищает ленту и снова показывает стартовую реплику.

### Раунд

1. Пользователь зажимает кнопку записи (или нажимает один раз — начать, второй — остановить, выбрать один вариант и не делать оба). Пока идёт запись, кнопка меняет вид и показывает таймер.
2. По остановке клиент отправляет blob на `/api/transcribe`, в ленте появляется заглушка `Слушаю...`.
3. Сервер прогоняет аудио через Whisper и возвращает текст. Клиент заменяет заглушку на реплику пользователя (сырая транскрипция) и ставит новую заглушку `Думаю...`.
4. Клиент отправляет на `/api/respond` историю и транскрипцию. Сервер вызывает модель, возвращает JSON с тремя полями.
5. Клиент заменяет заглушку на ответ бота (формат ниже) и добавляет `reply` в историю как реплику собеседника.

Пока идёт запрос, кнопка записи заблокирована. Перезаписать реплику нельзя: каждая новая запись — следующий ход диалога. Озвучки ответа нет, бот отвечает текстом.

### Ввод текстом

Под кнопкой записи — небольшое текстовое поле с отправкой по Enter. Работает так же, как голос, только пропускается шаг `/api/transcribe`. Нужно для отладки и для случаев, когда записать голос нельзя.

### Формат карточки ответа бота

Одна карточка в ленте, три блока:

```
Corrected: <исправленная реплика на английском>
<объяснение ошибок на русском, 1–3 строки; если ошибок нет — «Ошибок нет.»>
<следующая реплика собеседника на английском, выделена крупнее — это главное, что нужно прочитать>
```

Если исправленный текст совпадает с транскрипцией, блок `Corrected` всё равно показываем.

### Что кладётся в историю

В историю диалога попадает сырая транскрипция того, что пользователь реально сказал, с ошибками. Исправленная версия и объяснение в историю не попадают никогда, они только показываются. Это правило перенесено из полной концепции и его важно не сломать: если в контекст пойдут исправленные реплики, модель перестанет видеть, что человек на самом деле путает.

История, которую клиент шлёт на сервер, — последние 20 сообщений (10 пар). Старые отбрасываются на клиенте.

```ts
type Message = { role: "user" | "assistant"; text: string };
```

Для `assistant` в `text` лежит только `reply`, без corrected и explanation.

## Промпт и формат ответа модели

Системный промпт (черновик, можно править формулировки, нельзя менять набор полей):

```
You are an English conversation partner for a Russian-speaking learner (level around B1).
The user sends what they said out loud, transcribed automatically. Your job in each turn:

1. corrected — rewrite the user's sentence in correct, natural English. Keep the user's
   meaning and roughly their wording; do not make it fancier than needed.
2. explanation — in Russian, 1–3 short lines, explain the mistakes: what was wrong and
   why. If there are no mistakes, write exactly "Ошибок нет.". Ignore punctuation and
   capitalization, the input is a speech transcript.
3. reply — your next line as a conversation partner: 1–2 sentences, react to what the
   user said and ask a follow-up question. Stay on the current topic unless the user
   changes it. Plain spoken English.

Respond with a JSON object only: {"corrected": "...", "explanation": "...", "reply": "..."}
```

Вызов с `response_format: { type: "json_object" }`. В `messages` идёт системный промпт, затем история как есть, затем новая транскрипция как `user`.

Ответ парсится через `JSON.parse`. Если парсинг упал или нет какого-то из трёх полей — один повтор запроса, после второй неудачи роут возвращает 500, клиент показывает `Не получилось разобрать, попробуйте ещё раз.` и снимает блокировку с кнопки.

## API

`POST /api/transcribe` — `multipart/form-data` с полем `audio`. Ответ `{ text: string }`. Whisper получает файл через `toFile(buffer, "audio.webm")`.

`POST /api/respond` — JSON `{ history: Message[], userText: string }`. Ответ `{ corrected, explanation, reply }`.

## Обработка ошибок

- Браузер не дал доступ к микрофону → сообщение над кнопкой `Нужен доступ к микрофону`, текстовый ввод остаётся рабочим.
- Пустая транскрипция → карточка `Ничего не расслышал, скажите ещё раз.`, в историю ничего не пишется.
- Ошибка любого роута → карточка `Что-то сломалось, попробуйте ещё раз.`, полная ошибка в консоль сервера.
- Запись длиннее 60 секунд останавливается автоматически (лимит в константу).

## Порядок сборки

Каждый шаг доводится до рабочего состояния и проверяется в браузере, только потом следующий.

1. `create-next-app`, страница с лентой и текстовым полем, `/api/respond` пока возвращает эхо. Диалог с заглушками работает.
2. `llm.ts` с промптом и JSON, карточка ответа в три блока. История пока не передаётся.
3. История в состоянии, передача на сервер, лимит 20 сообщений, `Начать заново`.
4. Запись через `MediaRecorder`, `/api/transcribe`, `stt.ts`. Голос заменяет ручной ввод.
5. Обработка ошибок из раздела выше.

Дальше — только если всё выше работает: озвучка `reply` через OpenAI TTS (`tts-1`) и автопроигрывание в браузере. Это бонус, в план дня не входит.

## Чего в этой версии нет и делать не нужно

- Telegram, webhook, бот.
- Кнопок на карточках (разбор, сказать лучше, далее, подсказка).
- Сессий, таймаутов, сводок, подсчёта слов.
- Выбора темы, меню, профиля интересов.
- Базы данных, авторизации, сохранения истории между перезагрузками.
- Логов событий, счётчика расходов, уровней доступа.
- Поддержки других языков кроме английского.
